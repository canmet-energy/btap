## D-78 — Three-way verification for the Python migration: gates, run diffs, and direct oracle goldens

**Decided:** Verification for the Python migration is THREE-WAY, and all
three legs are explicit (2026-08-26): **Leg A** — Ruby gems ≡ the pinned
openstudio-standards oracle (the eleven in-process parity gates, unchanged);
**Leg B** — Python ≡ Ruby, by diffing both CLIs' `audit.json`/`report.json`
on the same models (`verification/compare_runs.py`, rules in
`verification/spec.json`, corpus in `verification/run_corpus.rb`); **Leg C**
— Python ≡ oracle DIRECTLY, against goldens frozen from the pinned oracle
(`test/goldens/oracle/`, exported by `scripts/export_oracle_goldens.rb`).

Leg C is direct, not transitive, on purpose: a bug faithfully ported from
Ruby to Python passes Leg B (both sides agree) and passes Leg A (Ruby still
matches the oracle) — only a comparison of Python against the ORACLE'S own
values catches it. The goldens are generated by the same probe code the
gates run (`test/support/oracle_probes.rb`), so gate and golden cannot
drift; `test/test_oracle_goldens_current.rb` (the twelfth pin-gated test)
re-verifies the committed files against the live oracle every parity run
and pins `manifest.legacy_ref == legacy_pin/REF` — bumping the pin without
re-exporting is a loud CI failure, never a silently stale golden.

The Leg-B differ is written in PYTHON from day one — the future side owns
the tool, and running it Ruby-vs-Ruby today is the harness's self-test
(zero-diff across the 18-run corpus proves pipeline determinism and no
false positives; a deliberate perturbation proves no false negatives).
Comparison rules live as DATA (`spec.json`): run-dir paths stripped,
absent ≡ null (the audit writer's `.compact`), pre-rounded numeric fields
exact, float-token normalization inside strings (Ruby `Float#to_s` and
Python `repr` render differently).
